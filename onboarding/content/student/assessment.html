Practical maintenance assessment — new proposal

This is a newly proposed assessment, pending reconciliation with the original QaaS Shampoo exam. It is not a recovered copy of that exam.

You receive a working disposable copy containing one bounded maintenance defect. A reviewer has observed incorrect behavior in a valid input case. Diagnose the cause and submit a safe repair with meaningful tests.

  1. Reproduce the baseline and the reported symptom. Record exact commands and observed results.
  2. Trace a real SoldierId through contract, input queue, transform, mock HTTP and output. Identify the earliest point where behavior diverges from expectations.
  3. Write an independent regression that fails on the defective version. Include explicit expected fields and the evidence needed to distinguish service, configuration and assertion failures.
  4. Make a small repair. Run the focused regression, relevant complete suites and the coordinated end-to-end batch. Preserve protobuf compatibility.
  5. Prepare a reviewable diff and handover with commits, CI URL and exact head, results, limitations, cleanup and rollback. Explain release impact and ownership boundary.

Submission: code diff, failing-before/passing-after logs, ID trace, test report, short diagnosis and review notes. See rubric. Ask for missing evidence when necessary rather than inventing it. CI blocked by unavailable access is reported as blocked; it is never replaced by a claim that local tests are CI.

Allowed: source code, official package documentation, the supplied runbook and normal development tools. During the unseen exercise, teacher seed instructions and answer sources are withheld by the instructor.
