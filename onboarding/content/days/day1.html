Day 1 — Reproducible baseline and one SoldierId

Goal: another person can repeat your baseline from the recorded commits. Budget: 6 focused hours.

  1. 0–1h: verify the prerequisites and sibling checkout layout in setup. Record SDK, Docker/Compose versions, commit hashes and API flag.
  2. 1–2h: run the isolated reset and baseline. Save exit code, baseline.json, stdout, Allure and CI URL (if available). Distinguish local results from remote CI.
  3. 2–4h: pick one generated SoldierId from the actual publication log. Trace its fixture and serialized input into the direct exchange/routing key, worker queue, transformer, GET buff, POST title, output exchange and consumer.
  4. 4–5h: inspect omega.proto. Explain tags 1–12 and output tags 13–20. Compare literal expected values with actual output. Identify where an output count could conceal a duplicated ID.
  5. 5–6h: reset and repeat once. Hand the commands to a peer to reproduce. Record any setup problem separately from a business failure.

Trace worksheet

Record: actual SoldierId; fixture row; serialized type; input exchange/queue/routing key; worker receive log; transform log; GET URI; POST request/response; output fields; publication log; consumer result; the assertion that checked it. Use measured evidence; mark any observation you could not capture.

Gate: clean reproduction and correct identity trace. A screenshot of a green count is insufficient. If prerequisites consume the day, use setup allowance and defer the gate.
