Day 4 — A bounded maintenance fix

Goal: repair one defect with a regression and understand its release boundary. Budget: 6 focused hours.

  1. 0–1h: reproduce a candidate defect in a disposable branch. Suggested learning cases: minimum signed lucky-number overflow or swallowed caller cancellation. Both are already fixed in the supplied reference, so the instructor must restore the old behavior in a disposable copy first.
  2. 1–3h: write a focused test with explicit expected behavior. Run it against the defective version and retain the failure output. Complete starter TODO C as a meaningful regression.
  3. 3–4h: make the smallest safe service fix. Review cancellation semantics, full signed integer domain and resource disposal. Preserve protobuf tags.
  4. 4–5h: run the focused test and relevant complete suites. Run the coordinated E2E stack. Review a diff containing only the intended change and required documentation.
  5. 5–6h: draft a PR explaining trigger, behavior before/after and validation. Match remote CI to the exact head commit. Explain whether this is application code, an external hook or framework core.

Release discussion: application/test changes do not require a QaaS Framework release. A published protobuf contract change requires a reviewed package version and downstream compatibility checks. Framework SDK/core changes ripple through Common packages, Runner/Mocker, mirror and docs; that is outside this bounded exercise.

Gate: preserved failing-before evidence, passing-after tests, a scoped reviewed diff and accurate CI status. A blocked CI run must be labeled blocked with its exact cause.
